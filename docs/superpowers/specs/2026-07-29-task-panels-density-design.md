# 下载任务与任务详情面板信息效率优化

**日期：** 2026-07-29  
**状态：** 已确认，待实施

## 1. 目标

在不改动下载流程、接口契约、轮询频率和现有 Industry 视觉体系的前提下，优化任务页中的“下载任务”和“任务详情”面板，使桌面端用户能更快完成以下判断：

1. 哪些任务正在运行、等待确认、失败或已结束。
2. 每个任务来自哪里、正在处理什么、完成到什么程度。
3. 选中任务后，当前文件、任务元数据和文件明细分别位于哪里。
4. 当前状态下有哪些可执行操作。

成功标准：

- 任务表由 8 个独立信息列收敛为 5 个稳定信息列。
- 标题、来源、类型和短任务 ID 在一个“任务”单元中形成明确层级。
- 进度与当前阶段放在同一单元，结果数字不再与进度重复表达。
- 选中任务具有清晰且可访问的选中状态。
- 普通任务、预扫待确认和预扫下载中的详情使用一致的头部结构。
- 现有任务操作、过滤、轮询和详情数据请求行为不回归。

## 2. 范围

本次仅修改：

- `module/templates/index.html` 中任务表、任务详情结构与对应渲染逻辑。
- `module/static/css/index.css` 中任务面板的局部样式与响应式规则。
- 与上述 DOM 契约直接相关的前端测试。
- `docs/web-control-console.md` 和 `progress.md` 中的使用与验证记录。

本次不修改：

- Flask API、任务状态模型、下载器、上传器或数据库。
- 任务过滤条件、轮询频率和状态转换。
- 任务清除、确认、取消或上传重试的业务规则。
- 其他页面的布局和视觉样式。
- 预扫包与文件之间当前缺少后端关联的已知限制。

## 3. 方案选择

采用“精简任务表 + 强化下方详情”的上下布局。

未采用左右主从布局，因为长标题、文件名和预扫包表格会压缩任务列表，并提高 1240px 应用外壳内的横向滚动概率。未采用行内展开，因为多个任务展开后会破坏列表的稳定扫描路径。

## 4. 下载任务面板

### 4.1 面板头

- 左侧保留“下载任务”和当前过滤结果数量。
- 右侧保留“全部 / 进行中 / 已完成”过滤。
- 过滤按钮继续使用现有按钮体系，但通过统一容器表达单选关系，并同步 `aria-pressed`。
- 空列表显示一行明确空态，不留下无内容表体。

### 4.2 表格列

任务表固定为以下 5 列：

1. **任务**：第一行标题；第二行依次显示来源、类型和短任务 ID。
2. **状态**：沿用现有状态标签映射。
3. **进度**：进度条、完成数量和下载/上传阶段说明。
4. **结果**：成功、失败、跳过三项等宽数字；仅失败数量大于零时强调。
5. **操作**：沿用现有状态对应操作，不新增业务动作。

“来源”“类型”“任务 ID”不再作为独立列，以减少横向扫视。“当前文件”继续只在详情中显示，避免轮询时任务行宽度抖动。

### 4.3 行交互

- 整行仍可点击选择任务。
- 选中行使用稳定浅色背景和左侧 3px 强调线，不使用阴影或动画位移。
- 行同步 `aria-selected="true|false"`，表体保留当前任务 ID。
- 点击行内操作按钮不得误触发行选择。
- 任务被清除或从轮询结果消失时，沿用现有逻辑关闭详情。

## 5. 任务详情面板

### 5.1 统一头部

详情头拆成两层：

- 第一层：任务标题、状态标签，以及当前状态允许的操作。
- 第二层：来源、类型、完整任务 ID、文件或包数量。

标题允许截断，但通过 `title` 保留完整内容。元数据保持低强调，不使用额外卡片或标签堆叠。

### 5.2 当前文件

仅在下载或上传状态显示。内容分为：

- 文件名：主信息，可截断并保留完整悬停文本。
- 当前阶段、进度和速度：辅助信息。

当前文件行位于详情头和明细表之间，避免与任务标题混在同一行。

### 5.3 明细内容

- 普通任务：继续展示文件表，统一表头、行高、文件名截断和进度列宽。
- 预扫待确认：选择摘要和确认操作保留在独立工具栏；包表沿用现有业务字段。
- 预扫下载中：整体进度放入详情摘要区域，包表仅展示已选择包。
- 三种详情共享相同的面板边框、头部间距、工具栏和空态样式。

本次不伪造单包进度，也不改变“展开包时只能取得任务级文件列表”的现状。

## 6. 数据与渲染

- `/api/task-dashboard` 继续驱动任务表和当前选中任务的摘要。
- `/api/tasks/<task_id>` 继续提供普通任务文件详情。
- `/api/prescans/<task_id>/packages` 继续提供预扫包详情。
- 渲染函数只重组现有字段，不派生新的业务状态。
- 详情异步请求返回时校验当前选中任务 ID，避免快速切换任务后旧请求覆盖新详情。

## 7. 错误与空态

- 任务过滤结果为空时显示与过滤条件对应的空态文案。
- 普通任务无文件时显示“暂无文件明细”。
- 预扫尚未生成包时保留“扫描中，等待生成资源包”的明确状态。
- 详情请求失败时在详情体内显示失败提示，不清空任务表，也不改变任务状态。
- 所有来自接口的标题、文件名、来源和错误文本继续经过 HTML 转义。

## 8. 响应式与可访问性

- 桌面端优先，在现有 1240px 应用外壳中尽量完整显示 5 列。
- 窄屏保留横向滚动作为兼容路径，不在本次引入移动端卡片模式。
- 表格行支持键盘聚焦与 Enter/Space 选择。
- 过滤按钮暴露选中状态；选中任务行暴露 `aria-selected`。
- 状态不能只依赖颜色，继续显示中文文字。
